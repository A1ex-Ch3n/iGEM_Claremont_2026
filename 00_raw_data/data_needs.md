# Data Needs — 00_raw_data

## Overview

This document explains what files are required for each organism, why each file is needed, and how it is obtained. It covers both **bacteria (hosts)** and **phages**, and documents known gaps and required follow-up actions.

---

## File Types: What, Why, and How

### For Bacteria (Hosts)

| File | Why | How Obtained |
|------|-----|--------------|
| `genome.fna` | Whole-genome nucleotide sequence. Required for: GC content (Factor 1), Prodigal input (Step 2), CAI codon extraction (Factor 6). | NCBI datasets CLI: `--include genome` |
| `proteins.faa` | NCBI-annotated protein sequences. Required for: pI/acidity (Factor 2), protein length (Factor 3), GRAVY hydrophobicity (Factor 4), sequence similarity BLAST (Factor 5), ESM-2 embeddings (Step 4). | NCBI datasets CLI: `--include protein` |
| `genes.gff` | Gene coordinates and feature annotation. Required for: identifying ribosomal protein genes for CAI reference set (Factor 6), structural annotation context. | NCBI datasets CLI: `--include gff3` |
| `cds.fna` | Pre-extracted CDS nucleotide sequences. **Critical for Factor 6 (CAI)**: host ribosomal protein gene CDSs are used as the high-expression reference set to build the codon usage table. Without this, CAI calculation requires manual GFF+genome extraction. | NCBI datasets CLI: `--include cds` |

### For Phages

| File | Why | How Obtained |
|------|-----|--------------|
| `genome.fna` | Whole-genome nucleotide sequence. Required for: GC content (Factor 1), PHANOTATE input (Step 2 annotation). | NCBI datasets CLI: `--include genome` |
| `proteins.faa` | NCBI-curated protein sequences (reference copy). Step 2 re-derives these via PHANOTATE, but the NCBI version is kept here for cross-validation. | NCBI datasets CLI: `--include protein` |
| `genes.gff` | NCBI gene annotation. Reference copy for comparison with PHANOTATE output. | NCBI datasets CLI: `--include gff3` |
| `cds.fna` | CDS nucleotides. Required for CAI calculation (phage codon frequencies computed against host reference table). | NCBI datasets CLI: `--include cds` |

> **Note on phage annotation pipeline:** `proteins.faa` and `cds.fna` for phages are also generated by PHANOTATE + pharokka in Step 2 (`02_annotation/`). The NCBI copies stored here are a reference baseline; the Step 2 outputs are what the feature-weighting pipeline actually uses downstream.

## Critical Issues in the Interaction Matrix

### Issue 1 — Duplicate accessions for different matrix columns

Two pairs of distinct organism names in the matrix share the same NCBI accession:

| Accession | Organism A (matrix column) | Organism B (matrix column) |
|-----------|---------------------------|---------------------------|
| `NZ_JBWJFR000000000` | *Xanthomonas arboricola* | *X. arboricola* pv. *pruni* |
| `NZ_CP150073` | *Xanthomonas oryzae* | *X. oryzae* pv. *oryzae* |

**Problem:** The ML model will receive two identical feature vectors for these pairs. Any difference in their interaction labels is noise by definition, because they point to the same genome. The classifier cannot learn a meaningful distinction between them.

**Solutions (discuss with Sarah/team):**
- **Option A — Merge:** Collapse the two columns into one in the interaction matrix. Use the more specific pathovar name and keep all positive interaction labels from both.
- **Option B — Separate genomes:** Find a distinct reference genome for the species-level entry. For example, *X. arboricola* (species) → use a different accession than pv. *pruni*; *X. oryzae* (species) → use a non-oryzae pathovar strain.
- **Option C — Drop one:** If the two columns have near-identical interaction profiles, drop the less specific one.

### Issue 2 — Negative pool phages not in interaction matrix

The 443 `negative_pool` phages have no rows in `final_interaction_matrix.csv`. Before ML training:
- All (negative_pool phage × Xanthomonas host) pairs must be added to the matrix with explicit label `0`.
- These should **not** be treated as missing data — they are structurally different from unobserved pairs.
- Pairs involving non-Xanthomonas bacteria (e.g., *E. coli* phage vs *Xanthomonas*) can reasonably receive label `0` without wet-lab confirmation.

## Do We Need More Bacteria?

The current 38 resolved bacteria (34 from matrix + 4 newly found) cover the major *Xanthomonas* pathovars well. The main gaps are:

1. **Xanthomonas translucens group** — only DSM 18974 added; if phages infecting *X. translucens* pv. *undulosa* or *cerealis* are relevant, add those.
2. **Xanthomonas hortorum** — currently unresolved (CFBP8638–8643). Adding the reference CFBP 8686PT would close this gap with one genome.
3. **Non-Xanthomonas hosts** — coverage is intentionally sparse (E. coli, Salmonella, Pseudomonas, etc.). These are present because some of our 777 phages infect them, providing structural negatives when cross-evaluated against Xanthomonas. No expansion needed unless the scope broadens.

**Recommendation:** Add *X. hortorum* pv. *vitians* CFBP 8686PT (GCA_012922135.1) as the one missing high-value bacterium. Hold off on further additions until the duplicate-accession issues are resolved and the truth table is updated.
